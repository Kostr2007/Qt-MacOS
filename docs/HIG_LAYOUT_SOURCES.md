# Layout and organization: проверенные источники

Проверено 8 ноября 2026 года по официальным Apple HIG и их DocC JSON. Это руководство по поведению и организации, а не обещание нативной реализации AppKit на Windows/Linux. Визуальный профиль библиотеки сохраняет традиционный macOS из пользовательских референсов; текущий Liquid Glass не смешивается с ним автоматически.

Индекс: [Layout and organization](https://developer.apple.com/design/human-interface-guidelines/layout-and-organization). Машиночитаемый источник: [DocC JSON](https://developer.apple.com/tutorials/data/design/human-interface-guidelines/layout-and-organization.json). Индекс — коллекция ссылок, рекомендации проверены в отдельных статьях ниже.

Для каждой строки доступны официальная статья и соответствующий DocC JSON по адресу `https://developer.apple.com/tutorials/data/design/human-interface-guidelines/<slug>.json`. Платформы взяты из `metadata.customMetadata.supported-platforms` и раздела Platform considerations, а не предположены по названию компонента.

| Статья / slug | Платформы Apple | Проверенные рекомендации и применение в Qt |
| --- | --- | --- |
| [Boxes](https://developer.apple.com/design/human-interface-guidelines/boxes) / `boxes` | iOS, iPadOS, macOS, visionOS | Небольшая группа связанных элементов; отступы и выравнивание предпочтительнее вложенных рамок. Краткий заголовок по необходимости. На macOS заголовок по умолчанию находится над группой. `MacBox` растёт по содержимому, использует спокойный фон и внешний необязательный заголовок. |
| [Collections](https://developer.apple.com/design/human-interface-guidelines/collections) / `collections` | iOS, iPadOS, macOS, tvOS, visionOS | Изображения — в стандартной сетке или ряду, с достаточным расстоянием для выбора/фокуса. Для преимущественно текстовых данных предпочтительнее таблица. В Qt коллекция показывает данные модели, а не фиксированную композицию. |
| [Column views](https://developer.apple.com/design/human-interface-guidelines/column-views) / `column-views` | Только macOS | Каждый столбец — уровень иерархии; первый — корень; выбор родителя открывает детей справа. Конечный элемент может иметь предпросмотр. Столбцы должны изменять ширину. |
| [Disclosure controls](https://developer.apple.com/design/human-interface-guidelines/disclosure-controls) / `disclosure-controls` | iOS, iPadOS, macOS, visionOS | Скрывать дополнительные детали, сохраняя основные действия видимыми. Подписанный треугольник направлен внутрь при закрытии и вниз при раскрытии. `MacDisclosureGroup` — именно disclosure triangle; отдельный disclosure button имеет другие направления и ограничение «не более одного на представление». Это ограничение не относится ко всем disclosure groups. |
| [Labels](https://developer.apple.com/design/human-interface-guidelines/labels) / `labels` | Все шесть платформ | Неизменяемый короткий текст, читаемый системный шрифт, семантические цвета важности. Полезные значения желательно разрешать копировать. `MacLabel` даёт роли и перенос строк; роли Title/Heading/Body/Secondary/Caption — API Qt-библиотеки, а не названия обязательных Apple-компонентов. Для копирования значений следует использовать read-only selectable TextEdit/TextArea: простой Label сам этого не обеспечивает. |
| [Lists and tables](https://developer.apple.com/design/human-interface-guidelines/lists-and-tables) / `lists-and-tables` | Все шесть платформ | Текст удобно сканировать в строках. На macOS — осмысленные заголовки, сортировка с изменением направления, изменение ширины столбцов, при необходимости чередование фона строк. Иерархия относится к outline view. |
| [Lockups](https://developer.apple.com/design/human-interface-guidelines/lockups) / `lockups` | **Только tvOS; явно не поддерживается macOS** | Контент, header и footer фокусируются как единое целое; согласованные размеры и расстояния. Масштабирование/наклон относятся к tvOS. `MacLockup` — адаптированная карточка изображения с метаданными для Qt, **не нативный паттерн macOS**. Автоматический перенос телевизионного parallax не является целью. |
| [Outline views](https://developer.apple.com/design/human-interface-guidelines/outline-views) / `outline-views` | Только macOS | Иерархия только в первом столбце, раскрытие родителей, сохранение выбора раскрытых ветвей, изменение ширины столбцов. Сортировка иерархии выполняется внутри каждого уровня. Простой плоский список с отступами сам по себе не заменяет дерево. |
| [Split views](https://developer.apple.com/design/human-interface-guidelines/split-views) / `split-views` | Все шесть платформ, с разным поведением | Выбор в ведущем pane объясняет содержимое следующего. На macOS: тонкий разделитель, перетаскивание, разумные ограничения ширины; скрытую панель можно вернуть несколькими способами. Адаптация к узкому окну не должна терять контекст выбора. |
| [Tab views](https://developer.apple.com/design/human-interface-guidelines/tab-views) / `tab-views` | macOS, watchOS | Близкие области содержимого, независимые состояния панелей и понятные подписи. Контрол сверху области; предпочтительно не более шести вкладок. На watchOS используются страницы; это не образец внешнего вида вкладок macOS. |

## Что дополнительно проверяется в Qt

Доступность через Qt Accessible, клавиши Space/Enter, видимый клавиатурный фокус, возврат фокуса из скрываемой области, отсутствие перехвата внешнего фокуса, светлая/тёмная тема и отключение анимации — требования реализации Qt. Не все эти конкретные механизмы описаны в перечисленных статьях Apple. Они проверяются поведенческими тестами отдельно от сравнения фотографий.

Нативные SwiftUI/AppKit API в статьях — ориентиры семантики. Эта библиотека использует Qt Quick, не встраивает SF Symbols или San Francisco и не выдаёт переносимые компоненты за системные Apple controls. Стандартный шрифт приложения наследуется; выбор альтернативного шрифта и лицензии ресурсов остаются отдельными решениями проекта.
